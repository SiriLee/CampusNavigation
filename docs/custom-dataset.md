# 实际场景微型数据集说明

> 数据文件位于 [`test_data/custom/`](../test_data/custom/)  
> 测试程序：`CampusNavigationCustomTests`（源码 [`tests/test_custom.cpp`](../tests/test_custom.cpp)）

---

## 数据来源

基于**简化的虚拟大学校园**场景构建。地点涵盖教学楼、食堂、宿舍、体育设施、医院、行政楼、校门和超市等典型校园 POI，道路模拟真实校园的路网结构。所有数据为手工设计，用于在可控的小规模图上验证导航算法的各项功能。

### 道路连接（26 条边，其中 24 条 open、2 条 closed）

道路设计模拟了真实校园的以下特征：

- **主干道**：北门（P013）→ 教学区（P001/P002/P003）→ 图书馆（P004）→ 食堂（P005）→ 宿舍区（P007/P008），形成贯穿校园的主要路径
- **闭环结构**：教学区（P001↔P002↔P003↔P004↔P001）形成多个三角形环路，确保教学区内部高度连通
- **备选路径**：P002↔P006↔P012 提供从教学区到行政区的替代路线，绕过食堂
- **桥连接**：食堂（P005）连接教学区与宿舍区，是多条最短路的必经节点
- **孤立区域**：南门（P014）和校园超市（P015）通过唯一道路连接，但与主校区无任何连通，模拟"未接入路网的独立区域"
- **封闭道路**：
  - `P012–P004`（行政楼↔图书馆，closed）——模拟施工中或临时关闭的路段
  - `P003–P010`（第三教学楼↔操场，closed）——模拟因故封闭的捷径
- **时间敏感节点**：校医院（P011）、行政楼（P012）在 17:30 关闭，学生食堂（P005）在 20:30 关闭，体育馆（P009）在 21:00 关闭，用于测试 `TIMED_SHORTEST` 的时间过滤功能

## 检验目标

本数据集设计为覆盖以下功能点：

### 1. 基本 CRUD 与查询

| 命令 | 验证点 |
|------|--------|
| `LOAD` | 正确加载 CSV 文件（含中文 display_name），无误返回 OK |
| `QUERY_PLACE P001` | 完整输出地点信息：ID、名称、类别、停留时间、开放/关闭时间 |
| `QUERY_PLACE P999` | 不存在的地点返回 `ERROR place_not_found` |
| `QUERY_CATEGORY Teaching` | 正确筛选并排序（P001, P002, P003），计数为 3 |
| `QUERY_CATEGORY NonExistent` | 空类别返回计数 0，无后续节点 ID |
| `ADJ P001` | 邻接边按 neighbor_id 排序，含 distance、walk_time、status |
| `ADJ P014` | 度数 1 的边界情况（仅连接 P015） |

### 2. 连通性分析（COMPONENTS）

- 正确识别 **2 个连通分量**（大小 13 和 2）
- 分量大小按降序排列

### 3. 最短路径（SHORTEST）

| 用例 | 验证点 |
|------|--------|
| `P001→P003` | DIST=220（经 P002），TIME=4。简单两段路径 |
| `P001→P007` | DIST=400（经 P005），TIME=7。必经食堂的单一路径 |
| `P013→P010` | DIST=950（经 P012），TIME=15。行政楼路线优于绕行教学区 |
| `P013→P015` | `NO_PATH` — 跨连通分量不可达 |
| `P014→P015` | DIST=200，TIME=3 — 孤立分量内路径，验证小分量也能正确规划 |

### 4. 时间敏感路径（TIMED_SHORTEST）

精心选择的时间点测试 TIME 过滤器的边界行为：

| 用例 | 验证点 |
|------|--------|
| `P001→P011 09:00` | 正常工作时间：三个节点均在开放时间内（P001: 07:00–22:00, P004: 08:00–22:00, P011: 08:00–17:30） |
| `P001→P011 06:00` | **起点未开放**：P001 在 06:00 尚未开放（07:00 开门），应返回 `NO_PATH` |
| `P005→P007 21:00` | **起点已关闭**：学生食堂 20:30 关门，21:00 不可用，应返回 `NO_PATH` |
| `P001→P007 12:00` | **正午时刻**：所有节点均在开放时间，作为正常工作的对照 |

### 5. 必经点路径（MUST_PASS）

| 用例 | 验证点 |
|------|--------|
| `P001→P007 DIST P005` | 必经食堂：路径 P001→P005→P007，DIST=400。P005 是唯一必经点且恰好在最短路径上 |
| `P013→P010 TIME P012` | 必经行政楼：路径 P013→P012→P010，TIME=15。验证 MUST_PASS 使用 TIME 模式 |

### 6. 最小生成树（MST）

- 图不连通 → 输出 `DISCONNECTED`
- 封闭边（P012–P004, P003–P010）不参与 MST 计算（仅取 open 边）
- 若仅考虑主分量，Kruskal 算法需正确处理封闭边

### 7. 关键节点/关键边（CRITICAL）

- **割点**：0 — 主分量是 2-连通图（最小度数 2 且无割点）；孤立分量中的 2 节点也不是割点
- **桥**：仅 1 条 — `P014–P015`（孤立分量内的唯一边）
- 验证算法不会将封闭边误判为桥
- 测试 `CRITICAL NODES 0 EDGES 1` 的边界情况（零割点、单桥）

### 8. 共享单车券（SHORTEST_K）

| 用例 | K | 验证点 |
|------|---|--------|
| `P001→P007` | 0 | 与标准 TIME 最短路一致（TIME=7，K_USED=0） |
| `P001→P007` | 2 | 使用 2 张券：P001–P005（walk_time 5→2）和 P005–P007（walk_time 2→1），totalTime=3 |
| `P001→P007` | 5 | K 超出路径边数，最优解仍为 2 张券（totalTime=3），验证 `usedK < K` 的语义 |

## 已知设计与局限

1. **P014–P015 孤立的设计意图**：模拟实际场景中"南门区域尚未接入校园主干路网"的情况，用于测试跨分量不可达（NO_PATH）和 DISCONNECTED（MST）
2. **封闭边不影响 CRITICAL 结果**：两条 closed 边均不在主分量的桥/割点分析中，预期不干扰算法输出
3. **MUST_PASS 的必经点恰好在最短路上**：这两个用例中必经点天然位于最优路径上，不会触发绕路行为。如需测试强制绕路，可设计必经点偏离最短路的用例
4. **数据不含重复边或自环**，均为简单无向图

## 测试：编译、运行与验证

### 编译

测试程序随主项目一同编译，使用 CMake + MinGW：

```bash
# 配置
cmake -B build -G "MinGW Makefiles"

# 编译（含所有测试目标）
cmake --build build
```

编译后将生成以下测试可执行文件：

| 可执行文件 | 测试数据 | 测试范围 |
|-----------|---------|---------|
| `build/tests/CampusNavigationTests.exe` | `test_data/must_do/` | 基础功能（13 个用例） |
| `build/tests/CampusNavigationExploreTests.exe` | `test_data/explore/` | 拓展功能 SHORTEST_K（4 个用例） |
| `build/tests/CampusNavigationCustomTests.exe` | `test_data/custom/` | 本数据集（1 个用例） |

### 运行

```bash
# 仅运行自定义场景测试
./build/tests/CampusNavigationCustomTests.exe \
    ./build/CampusNavigation.exe \
    ./test_data/custom \
    ./build/test_outputs_custom
```

预期输出：

```
PASS .
TOTAL 1 PASS 1 FAIL 0
```

### 通过 CTest 运行

```bash
ctest --test-dir build -R custom --output-on-failure
```

---

测试程序采用黑盒进程比对架构：以用例目录为工作目录启动被测程序，将 `command.txt` 重定向到 `stdin`，归一化（`\r\n`→`\n`、行尾空白裁剪）后与 `answer.txt` 逐行比较。全部测试程序共享 [`tests/test_common.h`](../tests/test_common.h)，测试架构的完整说明见 [README.md](../README.md#测试基础设施)。

### 判定准则（本数据集涉及的行类型）

| 行类型 | 严格字段 | 可放宽字段 |
|--------|---------|-----------|
| `PLACE` / `ERROR` / `OK` / `CATEGORY` / `ADJ` / `COMPONENTS` / `NO_PATH` / `DISCONNECTED` | **全部严格** | — |
| `PATH <MODE> <COST> NODES ...` | MODE、COST、首节点、末节点 | 中间节点（等代价替代路径） |
| `PATH <TIME> K_USED <K> NODES ... FAST <N> ...` | totalTime、usedK、首节点、末节点、FAST 边数 | 中间节点、FAST 边集合（集合比较，顺序无关） |
| `MST <DIST> EDGES ...` | 总距离、边数（token 数一致） | 具体边集合（同权边多种等价 MST） |
| `CRITICAL NODES <N> ... EDGES <M> ...` | 割点数、桥数、集合相等 | 割点/桥的输出顺序 |

### 本地手动验证

若测试失败，可单独运行被测程序并对比输出：

```bash
# 将命令文件喂给程序，输出到临时文件
./build/CampusNavigation.exe \
    < ./test_data/custom/command.txt \
    > ./build/my_output.txt

# 逐行对照
diff ./build/my_output.txt ./test_data/custom/answer.txt
```

也可查看测试程序自动保存的实际输出：

```bash
cat ./build/test_outputs_custom/._output.txt
```

如需验证某个具体命令的结果（如 MST 是否正确），可创建临时命令文件手动运行：

```bash
echo -e "LOAD places.csv roads.csv\nMST\nQUIT" | \
    ./build/CampusNavigation.exe
```

### 扩展用例

若需为本数据集增加测试命令，编辑 `command.txt` 追加命令，然后更新 `answer.txt` 为新的期望输出。建议先手动运行程序确认输出正确，再写入 `answer.txt`。注意 `QUIT` 必须是最后一条命令。

也可以通过复制现有目录结构来创建新的独立用例：

```
test_data/custom_extended/
  ├── command.txt
  ├── answer.txt
  ├── places.csv
  └── roads.csv
```

测试程序会自动发现任何包含 `command.txt` + `answer.txt` 的目录（支持嵌套子目录）。
